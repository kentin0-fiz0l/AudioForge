## ⏳ What Was Deferred to v1.1.1

### Intentional Scope Decisions:

**1. Code Signing (Deferred)**
- **macOS**: Code signing implementation exists, but certificate setup incomplete
- **Windows**: Decided to skip ($400/year cost saved)
- **Decision**: Ship unsigned for v1.1.0, add signing in v1.1.1 if adoption warrants
- **Impact**: Users see security warnings but can install with right-click → Open

**2. Windows Installer (Deferred)**
- **Status**: NSIS script ready, documentation complete
- **Blocker**: Requires Windows VM to build
- **Timeline**: v1.1.1 (next 2 weeks)

**3. Linux Packages (Deferred)**
- **Status**: Build script ready, automation script created
- **Blocker**: Docker build failed (JUCE submodules), needs proper Linux environment
- **Timeline**: v1.1.1 (next 2 weeks)

**4. VM Testing (Deferred)**
- **Status**: Can be done for v1.1.1
- **Reason**: Unsigned release doesn't require extensive testing
- **Timeline**: v1.1.1 with signed installers

## 🎓 Key Learnings

### What Worked Well:
1. **Incremental release strategy**: Ship macOS first, add platforms later
2. **Documentation-first approach**: Comprehensive guides enable contributors
3. **Automation scripts**: Linux VM script will save hours in v1.1.1
4. **Cost-conscious decisions**: Skip Windows signing until adoption proven
5. **GitHub-native approach**: Use built-in features (Releases, analytics)

### What Was Challenging:
1. **Cross-platform builds**: Docker/VM setup more complex than expected
2. **Code signing**: Apple Developer ID certificate setup unclear
3. **JUCE dependencies**: Building plugins from source requires proper setup

### Recommendations for v1.1.1:
1. **Windows**: Use native Windows machine or Parallels VM
2. **Linux**: Use Multipass or native Linux system
3. **Code signing**: Do certificate setup as separate session
4. **Testing**: Create VM snapshot templates for quick testing
